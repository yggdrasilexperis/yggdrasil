# Yggdrasil.Infrastructure

Everything that talks to the outside world: Postgres, ASP.NET Core Identity,
token signing.

**References:** Application, Domain, EF Core, Npgsql, Identity.

## Layout

```
Persistence/    YggdrasilDbContext, plus one IEntityTypeConfiguration per entity
Migrations/     generated by dotnet ef — checked in, never hand-edited
Repositories/   implementations of the Application/Abstractions interfaces
Identity/       ApplicationUser, password hashing, JWT issuing
Seeding/        demo data (card #9)
DependencyInjection.cs   one AddInfrastructure(config) extension method
```

## What belongs here

- The `DbContext` and the fluent EF configuration for each entity — column
  types, indexes, cascade rules, the `QuizCategory` join table.
- Repository classes implementing interfaces declared in Application.
- `ApplicationUser : IdentityUser<Guid>`, the password hasher, the JWT token
  service.
- One `AddInfrastructure(this IServiceCollection, IConfiguration)` extension so
  `Program.cs` wires this whole project up in a single line.

## Rules

- **Migrations are append-only.** Once a migration has been applied and pushed,
  never edit it — add a new one. Editing an applied migration breaks every
  teammate's database and the deployed one.
- Configuration is read from `IConfiguration`, which is populated from
  environment variables. No connection string is ever written into a file here.
- Application must not know which database this is. Keep Npgsql-specific types
  from leaking out through the repository interfaces.
